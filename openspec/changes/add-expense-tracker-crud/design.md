## Context

The `webapp/` folder is currently empty. This change scaffolds the first application in the workspace: an Angular 21 front-end that demonstrates a full CRUD feature (expenses) without a real backend. Per repo conventions (see `.github/copilot-instructions.md`), the app must use standalone components, signals, the new control flow, and `input()`/`output()`/`model()` APIs.

## Goals / Non-Goals

**Goals:**
- Stand up a new Angular 21 workspace at `webapp/` using the Angular CLI defaults for standalone apps.
- Implement a single `expense-tracking` feature with list, add, edit, delete backed by an `HttpClient`-based service.
- Simulate a backend using an in-memory HTTP mock so the service layer exercises real HTTP request/response flows (via `HttpInterceptorFn` or `angular-in-memory-web-api`-style handler) instead of returning static data directly.
- Keep the UI simple: one list view + one reusable form view, both standalone components with signals for state.

**Non-Goals:**
- No real backend/API integration or persistence beyond in-memory mock data (resets on reload).
- No authentication, multi-user support, or advanced filtering/sorting/pagination.
- No server-side rendering configuration beyond CLI defaults.

## Decisions

- **Mocking strategy**: Use a custom `HttpInterceptorFn` registered via `provideHttpClient(withInterceptors([...]))` that intercepts requests to a fake `/api/expenses` base URL and reads/writes an in-memory array, returning `Observable` responses with simulated latency. Rationale: keeps the service code identical to what it would be against a real REST API (`HttpClient.get/post/put/delete`), satisfying "http services with mock data" while avoiding a real backend dependency or extra library.
- **State management**: `ExpenseService` holds a `signal<Expense[]>` cache populated from the initial HTTP `GET`, updated optimistically after each successful CRUD call. Components read via `computed()`/the signal directly, avoiding manual subscription management.
- **Routing**: Two routes — `/expenses` (list) and `/expenses/new` + `/expenses/:id/edit` (form) — using lazy-loaded standalone route components via `loadComponent`.
- **Forms**: Reactive Forms for the add/edit form (Signal Forms are stable in v22+ per guidelines, but pinning to Angular 21 here per explicit user request, so Reactive Forms is the correct choice until upgraded).
- **IDs**: Expenses get a simple incrementing numeric `id` generated by the mock interceptor on create.

## Risks / Trade-offs

- [Mock data resets on every page reload] → Acceptable for a demo app; documented in README.
- [In-memory interceptor diverges from real backend semantics (e.g., no real error codes)] → Keep interceptor logic simple and return standard HTTP status codes (200/201/404) so swapping in a real API later is low-friction.
- [Angular 21 may not be publicly released] → Use the latest available Angular CLI version at scaffold time and document the targeted major version; adjust if the installed CLI resolves to a different latest version.
